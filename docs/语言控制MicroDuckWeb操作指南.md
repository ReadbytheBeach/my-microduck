# MicroDuck 语言控制 Web v2 · 完整操作步骤与解释

> 日期：2026-11-01。适用版本：M2 Web v2（实时校验 + 语音 + 视频节选）。
> 前置：`mdctl session start` 与 web 服务都用解释器 `work/dance/microduck_rl/.venv/bin/python`。

## 一、启动（两个终端窗口）

**终端 1 — 起仿真会话（鸭子本体）：**

```bash
cd ~/microduck-ros2-isaac
PY=work/dance/microduck_rl/.venv/bin/python
$PY -m language_control.mdctl session start --backend isaac --name voice01 --video
```

- `--backend isaac`：真实物理仿真（首次启动要 2~4 分钟编译加载，耐心等）
- `--name voice01`：会话名，自己起
- `--video`：**要画面必须加**。开启整段录像 + 每命令片段 + 预览帧（有 GPU 开销，默认关）
- 看到 `"state": "running"` 即就绪。注意 `--steps` 别传小值（那是会话总仿真预算，默认 200 万步够用很久）

**终端 2 — 起 Web 服务：**

```bash
cd ~/microduck-ros2-isaac
work/dance/microduck_rl/.venv/bin/python -m language_control.web --port 8787
```

终端会打印一行带 token 的 URL，浏览器打开它：

```
MicroDuck web client (local prototype): http://127.0.0.1:8787/?token=xxxx
```

页面打开后**自动连上最新的运行中会话**（就是 voice01），顶部"会话"栏会显示名字和状态。想换会话：输入名字点"切换"，不用改 URL。

## 二、页面各区域怎么用

页面最宽 1600px。**提案/网关与技能面板并排**（左输入、右技能表），对照着拼组合指令不用来回滚动。

### ① 提案/网关（左上，输入区）

输入框下方是控制区（自上而下）：

- **export MOONSHOT_API_KEY=...**（按钮）：页面内配置 Kimi 密钥——点击弹窗粘贴 key，**只存 web 进程内存，不写盘、不入账本**，旁边显示状态（已配置+尾号 / 来自环境变量 / 未配置）；留空提交=清除。也可照旧用环境变量 `MOONSHOT_API_KEY`（或 `KIMI_LC_API_KEY`），页面配置的 key 优先
- **2.语音**：点一下开始录音（首次浏览器弹麦克风权限，允许），再点"■ 停止录音" → 回显"我听到的是：……"并自动校验 → **确认转写无误后点 3 才执行**
- **3.发送并规则解析**：正式递交执行（详见下方"发送按钮在做什么"）
- **1.选中则使用Kimi模型解析/或规则匹配**（开关，在 3 的右侧）：不勾=只用本地规则（快、免费、只认"说法"列的句式）；**勾上=Kimi 先理解**。Kimi 看到的技能清单就是右侧技能面板那份数据（注册表接地），能听懂自由表述、**多步序列**（"往前走两秒然后停下歇一秒"）和**参数**（方向/时长/走多少厘米），不可用技能它会诚实拒答。Kimi 不可用（没配 key/超时）自动回退规则解析。**无论哪条路，网关判决不变**——LLM 只负责听懂，放不放行还是网关说了算

辅助反馈：

- **网关校验(规则判定)**：打字停半秒自动预检，只给一行短结论——🟢 ✓ 可执行（n步,Kimi理解/规则解析）/ 🔴 ✗ 不可执行（分类）。**长原因收进悬停提示**（鼠标放上去看），完整细节在"动作结果"区。它只是机械校验结论；理解内容看下行
- **匹配结果**：绿色一行显示解析出的行动序列，如 `walk_backward(vx=-0.3,sim_duration_s=3) → ground_pick`——这是理解层的主要输出，发送前先审计匹配得对不对。**即使网关拒绝也显示**，方便对照"它听懂了什么 vs 网关为什么拦"
- **"你是不是想说：……"**：解析失败时给出最接近的说法建议（比如打了"向后推"→提示"向后走/退后/后退"），只建议不执行；语音转写错字时特别好用
- **"停下"**：不管打字还是语音，命中立即停止，不等任何确认——这是安全后门
- 转写错了怎么办：直接在输入框里改文字再发，或者说"停下"重来

### ①补 "发送"按钮在做什么

输入框是**草稿**，可执行性预检是**免费问询**（只查不执行），点发送是**正式递交**。递交后：停止短语检查 → 解析（规则或 Kimi）成提案 → 网关安检（技能登记/状态/限值）→ 会话服务排队 → Isaac 执行 → 回执显示在"动作结果"。每一站都可能拒单并给出原因。

### ② 技能面板（右上，对照表）

- **表格上方是模型路径列表**：每个技能绑定的 ONNX 文件（如 `walk: reference/policies/v7/velstand.onnx`），stop 是内置技能无模型
- 表格列：skill（英文名）| **技能（中文名）** | **说法（能听懂的全部中文短语，带方向/数值标注）** | usage | evidence | 可执行
- 说法列示例：`向前走(前进0.15m/s)`、`向后走(后退0.15m/s)`、`向左转(左转0.5rad/s)`——前进/后退/左右移/转向一目了然
- 拼指令直接照着"说法"列念/打字即可；**可执行 ✓** 的才会真正跑，✗ 的会被网关拦下并给出原因
- 可执行的目前是同策略家族（walk 前进/左右移/转圈、**walk_backward 后退**、stand、stop、闭环走距离）
- evidence 含义：passed=真实仿真核验通过（范围限定）、pending=核验未达判据、unknown=未核验、failed=核验未通过

### ③ 执行进度 + 停止按钮

- 实时显示仿真状态（当前速度、位置、步数）
- 红色"■ 停止"随时可按，独立通道，不被任何东西阻塞

### ④ 仿真画面（--video 启动才有）

- 上方预览图：约 1 秒刷一帧（视窗 480px），看鸭子"正在动"
- 下方片段列表：**每条命令一个 mp4**（文件名 `0001_xxxxxxxx.mp4` 按命令顺序编号），点击即播。刚执行完的命令几秒后出现。面板顶部显示片段所在目录；同名会话重新 `session start` 会清空上一轮的 session.mp4/预览帧/片段，**列表里永远是本次会话的片段**（要留存请先复制走）
- 想复盘"刚才那步走成什么样"→ 点最新片段；整段录像在 `work/language_control/sessions/voice01/session.mp4`

### ⑤ 动作结果

最后一条命令的完整响应（completed/failed + 原因）

### ⑥ 历史

最近的原文→提案→网关判定流水

## 二补、能听懂的说法（2026-11-01 扩充）

**勾选 Kimi 开关后不限于下列句式**：模型对着技能面板做匹配，自由表述、多步序列、参数（时长/距离/方向）都能提取，网关照旧卡控；不勾选时规则解析只认下列说法：

- **走**：向前走/往前走/前进/走/走路/朝前走/向前进/往前（默认 0.15 m/s）；向左走/往左走/左移；向右走/往右走/右移；左转/向左转；右转/向右转；原地走
- **后退**（独立技能 walk_backward，available+passed）：向后走/后退/往后走/倒退/退后（默认 -0.15 m/s），可加时长："向后走两秒"
- **时长/距离修饰**：走两秒/走2.5秒；向前走30厘米/走0.3米（闭环，自动停）
- **站**：站立/站好/站着/站住/站定/站直/别动/站着别动/保持站立
- **停**（立即执行）：停止/停下/停/停住/别走了
- **以下能听懂但网关会拦**（诚实拒绝，不猜）：坐下/坐下去、站起来/起立/起来、翻跟头/打个滚/滚一圈、左踢/踢左腿、右踢/踢右腿、蹲下/下蹲/蹲一蹲、捡东西/把东西捡起来——对应技能 evidence 为 pending/unknown 或编码未在会话启用；"跳个舞"等泛指舞蹈词明确判 capability_gap
- **序列**：用"然后/接着"连接，如"向前走两秒，然后站住"
- **打错了也没关系**：解析失败会提示"你是不是想说：……"（最接近的说法建议）

## 三、推荐玩法顺序

1. 先打字发一条"向前走两秒"，看预览图里鸭子走 + 片段列表出现 0001 片段
2. 再试语音说同样的话，体验"回显→确认→执行"
3. 试一句会被拒的（"给我跳个舞"），看红色拦截提示——网关在工作
4. 走的过程中按一次"■ 停止"，鸭子应立即站住
5. 试闭环："向前走30厘米"（走准了自动停，终点误差厘米级）

## 四、结束

```bash
$PY -m language_control.mdctl session stop --name voice01   # 终端1
# 终端2 直接 Ctrl-C
```

## 五、背后发生了什么（一图流）

```
你(打字/语音) → 浏览器
  语音: MediaRecorder 录音 → 上传 → sherpa-onnx 本地离线转写(不出本机)
  文字/转写 → /api/check 只校验不执行(解析+注册表+限值+闭环全查一遍) → 绿/红提示
  点发送 → SequenceParser 规则解析 → 提案 → 网关白名单 → 会话服务
    → 命令文件 → Isaac 播放进程(鸭子动) → ACK/结果回传
  同时: 播放进程 camera → ffmpeg → session.mp4 + 每命令片段 + 预览帧 → 页面
安全兜底: 转写回显确认 + check 预检 + 网关拦截 + 停止独立通道,四层
```

## 六、常见问题

- 页面灰/报 session not found → 会话没起或已退出，终端 1 重新 start（web 不用重启）
- 无预览帧 → 会话没加 `--video`
- 语音按钮报错 → 浏览器没给麦克风权限，地址栏左侧小锁图标里改
- 鸭子站定后新指令不走 → 这是已知的 velstand 策略层"站立不动吸引子"，停掉会话重开即可（已立项待处理，不是 Web 的问题）
- 想保留语音音频 → web 启动加 `--keep-audio`（存 `sessions/<name>/audio/`，账本记留存标记）
